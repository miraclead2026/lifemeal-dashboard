ID를 모르면 그 액션은 ID 없이 outputCode/planName만 넣고 needsConfirm=true. - 세부실행계획(subplan)에는 KPI 필드가 없다. KPI 관련은 level:"kpi" 로 따로. subplan 액션에 kpi 넣지 말 것. - stage 값은 정확히 "예정","진행중","검토중","완료","보류" 중 하나. - add(신설)와 edit(기존 항목의 상태/날짜/이름 변경)을 명확히 구분. - 날짜는 "YYYY-MM-DD". 숫자(목표값 등)는 number 타입, 콤마·단위문자 금지. - UTF-8(ensure_ascii 끄기). 토큰은 환경변수, 로그 노출 금지. ━━━━━━━━━━━━━━━━━━━━━━━━━ [6] 확인 ━━━━━━━━━━━━━━━━━━━━━━━━━ 회의록 JSON 만든 뒤: - data/meetings/(날짜).json 과 index.json 이 둘 다 push 됐는지 - actions 개수, 각 액션의 op/level/planId/subplanId/owner 요약을 출력
